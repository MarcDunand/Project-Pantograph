Project Pantograph · draw2axi

Meeting Log

A dated, meeting-by-meeting record of how the project has developed — a narrative of what we were trying to do and why, not just a code changelog. Technical detail lives in AGENTS.md; this is the story around it.

In one line: an artist draws on an iPad with an Apple Pencil and an AxiDraw pen plotter physically recreates the drawing, live, on paper — a "collaborative drawing machine" where the human leads and the machine follows.

Pipeline:
Apple Pencil → iPad (iDraw OSC app) → Wi-Fi (OSC) → Python → AxiDraw

Collaborators: Marc and Gina.

Roles: Marc leans toward the engineering side and Gina toward the artist side, but the two of us evaluate the output equally — both judging what comes off the plotter and steering the calibration together.

Note on the earliest work: the June 15 meeting predates our Claude sessions, so it's reconstructed from git history and the context doc. The June 12 work below was not an actual work session — it's the initial commit's groundwork, recorded here for completeness.

Groundwork · not a work session June 12, 2026

Foundation groundwork

Reconstructed from git history (initial commit) and AGENTS.md. Not an actual meeting — noted here for context.

Stood up the core of the system: the OSC receiver and the first end-to-end pipeline from iPad to plotter.

  • Chose iDraw OSC as the input path after weighing alternatives (Procreate had no live stroke API; a native PencilKit iPad app was 2–3 weeks of work; browser/WebSocket was simpler but less precise). iDraw OSC streams Apple Pencil position/pressure/tool data over Wi-Fi as OSC messages — no TouchDesigner needed.
  • Built listen_to_idraw.py: OSC dispatcher, a single state dict updated by every message, canvas→paper coordinate mapping with aspect-ratio letterboxing, stroke-boundary inference by time gap (no explicit pen-up messages exist), RDP stroke simplification, and a decoupled plotter thread so blocking motor calls don't stall OSC reception.
  • Wrote AGENTS.md, the standalone context document for the project (dated ~June 14).

At this point pressure was assumed to be always 1.0 — we hadn't yet realized that only comes from a finger, not the Pencil.

Full live pipeline + preview

Reconstructed from git history. Commit: "Fully functioning pipeline from idraw osc to computer preview to live axidraw strokes."

Meeting 2 June 23, 2026

Variable pressure & pen control

First Claude-assisted session.

The theme was making the pen's physical depth respond to how hard the artist presses — the first step toward the plotter feeling like a real brush/pen rather than a constant-depth tracer.

  • Started by surveying every feature currently implemented, to get oriented.
  • Key discovery: pressure only reads 1.0 when drawing with a finger; the Apple Pencil sends real variable pressure. This unlocked the whole pressure-driven direction.
  • Built a "Pen" subsection under Plotting with a new variable-pressure mode:
    • Min pen down (always active) — depth at ~zero pressure, or when variable pressure is off.
    • Max pen down (variable mode only) — depth at full pressure; linear scale between the two.
    • Pen up — always active.
    • A test button on each of the three sliders to jog the pen to that position for calibration.
  • Hit a bug where the sliders didn't actually move the pen; traced it into the installed pyaxidraw source and fixed it (positions must be re-pushed to the EBB board via ad.update()). Confirmed working.
  • Calibrated the pressure scale to the real OSC range: pressure actually runs 0 → 4.16667, not 0 → 1.
  • Diagnosed plotter stutter: the delay is the servo physically moving the pen up/down. Added constant-pressure-update handling plus a setting for what percentage of points actually push a new pen depth — fewer updates = less stutter — while guaranteeing true pen-up / pen-down commands always still fire.
Meeting 3 June 25–26, 2026

Canvas tilt & pressure-glitch cleanup

Session ran late into the night of the 25th.

Now that pressure drove pen depth, physical imperfections in the setup started showing up in the plotted output. This meeting was about compensating for the real-world rig.

  • X-tilt / Y-tilt parameters: the canvas isn't perfectly level relative to the AxiDraw, so with a paintbrush the stroke faded near the top of the page and went heavy near the bottom. Added tilt angles (in degrees) that adjust pen depth across the sheet to cancel the slope, exposed in the Plotting UI.
  • Pressure-glitch filter: occasional spurious pressure spikes appeared near stroke start/end. First approach interpolated out any 0.24 value from its neighbors (and dropped/errored on a stroke that was entirely glitched). Then refined it: detect the underlying raw 1.0 value directly instead, so we don't accidentally delete legitimate 0.24 pressures.
  • Committed as "added a bunch of new UI settings, many around calibrating the plotter."
Meeting 4 July 10, 2026

Flip axes as "set and forget"

Short, focused session.

A usability fix born from calibration friction: the Flip H / Flip V controls interacted badly with the tilt controls — flipping the canvas silently swapped which physical axis X-tilt / Y-tilt affected, so you had to mentally re-map every other setting.

  • Reordered the transform so Flip H / Flip V apply first, as a genuine "set and forget." After that, X always means the same physical dimension no matter the flip state, so tilt (and everything downstream) stays intuitive.
Meeting 5 July 16, 2026

Post-processing effects + SVG replay

Long session, ran past midnight into July 17. A big conceptual leap.

Two important things happened: the system gained a real post-processing effects framework, and we reframed SVGs as replayable input rather than just static output.

  • Calibration test pattern: shrank the test circle to 1 mm and made the circle → line → circle shape a single pen-down so it draws in one continuous motion.
  • Perpendicular pressure lines (first real effect): after each stroke, at every point where pressure exceeds a threshold (30% of max), go back and add a short line perpendicular to the stroke — length scales from 1 mm up to 3 mm with force above the threshold. All values abstracted out to be tunable. This seeded postprocess.py, whose architecture treats an effect as a transform over the plot command stream (moveto → pendown → lineto × N → penup), so an effect can rewrite, drop, or expand commands, and everything it emits still flows through the RDP optimizer.
  • The reframe: we want an SVG to behave like live iDraw OSC input — record the points as the artist drew them, then re-run optimization and post-processing over them. Non-determinism is fine and wanted: the goal is to recreate the same drawing many times with different post-processors in play.
  • SVG upload & "plot svg": added a UI option to upload and plot an SVG, with the requirement that a drawing downloaded and re-uploaded reproduces the exact same input data. Also added a centerline width = pressure option.
  • log_to_svg.py: we had a drawing we'd lost — but the terminal still held the full printed list of points. Wrote a tool to reconstruct a plottable SVG from the terminal log (position, pressure, tool, stroke boundaries), in the same format the preview downloads, so it can be re-plotted and run through the post-processors.
Meeting 6 July 17, 2026

Bug hunting + the mirror effect

Afternoon session, distinct from the late-night July 16 work.

With replay and post-processing in place, this meeting was shaking out bugs in the new replay path and adding another effect.

  • Double-plot bug (diagnosed here, fixed later): plotting an uploaded SVG often drew it twice. Root cause found — during replay the server broadcasts each replayed point back to the browser, and the browser records every incoming point, so a replay silently re-records the drawing into the canvas, doubling its geometry; downloading then saves the doubled version. Verified this is doubled file geometry, not a double dispatch. The fix was deferred at the time pending a UX choice, and later resolved as animate but don't record: replayed points are tagged at the source, so the browser draws them normally but never adds them to the recording.
  • Mid-plot stop bug: a plot stopped ~25% of the way through with no error — investigated the hypothesis that the program thinks the plot finished while the SVG still has lines to draw.
  • Mirror effect (new post-processor): some strokes are drawn both normally and mirrored vertically over themselves, governed by two parameters — mirror thresh (max stroke length eligible to be mirrored) and mirror chance (probability an eligible stroke actually gets a mirrored copy).

Meeting 8 July 23, 2026

Documentation + standalone SVG transforms + replay-crash fix

Two sessions across the day — a midday write-up and a longer evening of code.

Started by writing this meeting log. The evening then split into two threads: finally killing the mid-plot stop bug, and building a new offline SVG tool that sits alongside the post-processors.

  • Wrote this meeting log — a dated history of the project's development for our own reference and for anyone we bring in later.
  • Mid-plot stop bug — root cause found and fixed. The "plotting an SVG stops after a fraction" symptom turned out to be a thread data race: the pen-up watchdog and the replay thread both touched pen state (_pen_is_down / _last_plot_pt) with no synchronization. Because the pen-up timeout (0.15 s) is shorter than the replay max gap (0.30 s), the watchdog routinely fired between replayed points and nulled _last_plot_pt mid-emit — crashing the replay thread. That thread died silently, so points stopped flowing while the main and AxiDraw threads kept running (which is why "go home" still worked, and why it kept plotting a queued backlog for a moment after). Fixed with a reentrant _pen_lock guarding the whole pen-state read-modify-write in both functions, with the network broadcast kept outside the lock. This closes the open bug from the previous log.
  • "AxiDraw falling behind live" — understood, not a defect. Confirmed the lag (seen as lag=29–66s) is soft and self-limiting: the adaptive distance filter and the RDP optimizer thin points more aggressively as lag grows, and the replay deque is finite per drawing. The accepted trade-offs: fidelity intentionally coarsens with lag, control commands (stop/home) queue behind the backlog, and the same 0.15-vs-0.30 mismatch can fragment strokes during replay. Left as-is for now.
  • New tool — svg_transform.py: a sibling to the post-processors, not one of them. Post-processors run live inside the plotting pipeline on the point stream; these run offline on a finished plot SVG as a separate, hand-invoked step, in a tkinter GUI. Transforms: flip horizontal / flip vertical (mirror each stroke about its own canvas center), and filter by min width — a 0–100% slider that keeps only strokes at least that fraction as thick as the thickest stroke (whole-stroke, with a max/mean thickness toggle). Utilities: open, a live Preview with side-by-side Original vs Result, a kept/dropped stats readout, Reset, and Save.
  • Correctness cornerstone: re-plotting reads only the SVG's <metadata> recording, so every transform rewrites that recording (the source of truth) and regenerates the cosmetic visuals from it — the saved file re-plots exactly as previewed. Verified against a real 221-stroke / 33k-point drawing.
Meeting 9 August 5, 2026

Remote (no-AxiDraw) version + dot healer

Late-afternoon session, four threads in about two hours.

The theme was decoupling drawing from plotting — letting a drawing be made in one place and plotted in another, later — plus a new offline tool to repair a specific capture artifact.

  • Wrote up the July 23 meeting in this log (merging that day's two sessions into a single entry) to bring the history current.
  • Confirmed how stroke ordering is encoded. It isn't in the visible SVG shapes at all — the <path>/<circle> elements are cosmetic and the plotter never reads them. Ordering is purely array position inside the <metadata> recording: the strokes array is drawn in order, and each stroke's points array likewise. The per-point timestamp t only paces replay — it doesn't define order or stroke boundaries. So reordering means reordering the array; there's no z-order attribute to touch.
  • New: remote/ — a standalone no-AxiDraw version. Draw on the iPad, watch the preview, download a correctly-formatted plot SVG, and plot it on the real machine whenever you next have access to one. Two reasons: it lets Gina draw without needing Marc's plotter, and it makes the project useful to people who don't own an AxiDraw once we publish. Built as a genuinely independent version — listen_to_idraw_remote.py (OSC listener + stroke segmentation, no plotter thread, optimizer, effects, coordinate mapping, or pen/tilt controls) and preview_remote.py (one raw-OSC drawing layer, one export). Dependencies drop to just python-osc + websockets. (Later renamed iDraw_to_svg/.)
  • The cross-version contract. Because both versions must produce the same file, we pinned down exactly what's shared — the point broadcast shape plus PEN_UP_TIMEOUT_SEC segmentation, and the draw2axi-recording v1 metadata JSON — and wrote "change one, change both" into a header block in each remote source file, remote/README.md, and project memory. Verified end to end by sending real OSC, building the SVG exactly as the browser JS does, and feeding it through the full tool's own reader (svg_transform.py): it loads, transforms, and round-trips with the points preserved bit-for-bit. One real bug surfaced in testing — _pen_lock has to be a reentrant lock, since _emit_point holds it while calling _maybe_pen_up; a plain Lock deadlocks. (The same lock the July 23 race fix introduced on the full side.)
  • New tool — dot_healer.py: repairs strokes the capture tore apart. When the pen moves fast, iDraw's points arrive far enough apart in time that the pen-up timeout fires between them, chopping one continuous line into a trail of single-point strokes — visible in the SVG as the line ── • • • • ── line signature. Since replay draws each recording stroke as one uninterrupted pen-down, the heal is to merge each such run back into a single stroke. Guards keep deliberate taps safe: the run must be bracketed by a real (≥2-point) stroke on both sides, every hand-off must be within --max-gap, and strokes must share a canvas and tool. Like svg_transform.py, it rewrites the recording and regenerates the visuals from it.
  • Tuning it against real drawings. The session produced three new drawings that afternoon — tree, dense, and inkblot — and the latter two are exactly where the tearing shows: drawing_dense.svg came off at 3,185 strokes for only 73k points and drawing_inkblot.svg at 3,483 strokes for 56k points, i.e. mostly one-point fragments. That's what prompted the tool. We then dropped the original "at least 2 dots" rule so a single bracketed dot heals too, folding drawing_dense down to 385 strokes (133 runs, 2,263 dots reconnected) while an already-clean file heals nothing. Reviewed a healed result and confirmed the default --max-gap (6% of canvas diagonal) reconnects genuinely-torn strokes without welding separate marks.
Meeting 10 August 7, 2026

Tutorial-forward README + Tailscale for locked-down networks

Afternoon/evening session, three commits reworking the README end to end.

Shifted the README from a terse technical reference into a from-scratch onboarding tutorial, aimed at someone with no prior Python or command-line experience — a step toward handing the project to people outside the two of us.

  • New Setup walkthrough: numbered steps from getting the code (ZIP download or git clone) through installing Python, opening a terminal in the right folder, installing dependencies, and installing iDraw OSC on the iPad — splitting into Path A (with an AxiDraw) and Path B (preview/export only, no AxiDraw needed).

Installing Tailscale on both devices and pointing iDraw OSC at the computer's Tailscale IP (tailscale ip -4) routes around that restriction — works on any network, not just an open one, since the devices no longer need to reach each other directly.
  • Readability + de-duplication pass: reworked phrasing throughout the tutorial and removed information that was now redundant with the later technical sections, so each fact lives in one place. Also fixed a stale path reference in iDraw_to_svg/README.md (remote/saved_drawings/ → iDraw_to_svg/saved_drawings/, left over from the earlier remote/ → iDraw_to_svg/ rename) and dropped a reference to log_to_svg.py from the recording-format contract list, since that tool doesn't read the format.
Meeting 11 August 28, 2026

Filmed live demo + the last replay bug closed

A demo shoot, then a long session of code and documentation.

The session the project has been building toward: we filmed a demo of live Project Pantograph control — Gina drawing on the iPad while the AxiDraw concurrently recreated her drawing on paper. That's the whole premise of the machine, working, on video. The rest of the session went to clearing the last known bug and making the project easier for a newcomer to pick up.

  • Final video demo: live end-to-end control captured on video — Gina drawing and the plotter reproducing the strokes as she made them, concurrently rather than after the fact.
  • Double-plot bug — fixed. The re-record bug diagnosed back on July 17 and deferred ever since. We picked the UX that had been the open question: animate but don't record. Replayed points are now tagged at the source — a thread-local flag on the replay thread adds replay: true to each broadcast, chosen over a plain global because live drawing and a replay can be in flight on different threads at once. The browser latches that flag once per stroke, from the first point, deliberately not from the pen-up message: _maybe_pen_up can fire from either the replay thread or the watchdog, so a flag on that message would have let the bug straight back through.
  • Four guard sites, not one. Beyond the obvious two (don't accumulate raw points, don't push to completedStrokes), two were easy to miss: allStrokes() deliberately includes the in-progress stroke, so a download mid-replay would have captured the playback; and clearCanvas() / applyPreviewSize() both reset stroke state and would have left a sticky flag behind.
  • Verified rather than assumed. Three levels: end-to-end over real OSC and WebSocket in --dry-run (5 live points tagged false, 7 replayed tagged true, no leakage); the real browser module loaded under a DOM stub and driven directly through six cases; and the bug itself — draw two strokes, replay them, confirm the recording is byte-identical before and after, then export through the page's own writer and read it back with svg_transform.load_svg to get 2 strokes, not 4. dot_healer and svg_transform self-tests still pass.
  • README — the Terminal/PowerShell confusion. Sorted out a genuine trip-up: on Windows these are two layers, not two choices — Terminal is the window, PowerShell is the shell running inside it, which is why opening Terminal prints "Windows PowerShell" on line one. The guide now says "terminal" throughout, explains that distinction where a newcomer first meets it, and notes the Windows 10 fallback. One instruction had to keep the old name: the File Explorer address-bar trick takes a program name, and there is no program called terminal — so powershell stays there, with a note saying why. Also reconciled a pre-existing dir-vs-ls inconsistency in favour of ls, which works on both platforms.
  • Tooling: gave Claude standing permission for shell, file, search, and web tools in .claude/settings.local.json (gitignored, so the broad grant never lands in the repo) rather than approving each command as it came up.

Where things stand

  • Live pipeline (iPad → preview → AxiDraw) is working.
  • Pressure-driven pen depth, tilt/flip calibration, and a percentage-based update throttle for stutter are all in.
  • A post-processing framework (postprocess.py) exists with perpendicular pressure lines, mirror, and centerline-width-from-pressure effects, plus SVG upload/replay and terminal-log reconstruction.
  • Standalone offline tools sit alongside the live pipeline, each rewriting the recording and regenerating visuals from it: svg_transform.py (GUI — flip H/V, filter by min width) and dot_healer.py (rejoin strokes a fast pen tore into a trail of dots).
  • A no-AxiDraw version (iDraw_to_svg/, originally remote/) records drawings to plottable SVGs for plotting later on the real machine — its recording output must stay in sync with the full version.
  • Both replay bugs are fixed — the mid-plot stop (thread race) and the double-plot re-record.
  • Demoed live on video: Gina drawing while the AxiDraw concurrently recreated the drawing on paper.
  • Known open items: preview rendering quality (smoothing) remains a longer-term want from the early plan.
